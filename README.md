# Steam reviews of ELEX: data and results

Data, intermediate outputs, results and analysis scripts of the use case of the paper: the Steam reviews of *ELEX*
(Piranha Bytes, 2017; Steam app 411300), analyzed with the review pipeline published in a separate repository:
[Design practices from Steam reviews](https://github.com/sbassanelli/Design-practices-from-Steam-reviews).

Everything needed to check or reproduce the numbers, tables and figures of the paper is here: the reviews, every model output, the
codebook, the final coded extracts, the design brief, and the scripts that compute the results.

## Data

- **Source:** public Steam reviews, collected on 5–6 November 2026 through the public store review endpoint
  (`store.steampowered.com/ajaxappreviews/411300`), all languages: 19,645 of the 19,646 reviews reported by Steam.
- **Author identifiers:** author Steam ids and profiles were not stored. Reviews keep their public Steam review id
  (`recommendationid`), their text and the fields that Steam publishes with them (language, date, recommendation, playtime of the
  author, purchase type, votes).
- **Population:** copies bought on Steam, excluding copies declared as received for free.

| Step | Reviews |
|---|---|
| Collected | 19,645 |
| Not bought on Steam (keys from other stores) | −7,185 |
| Declared as received for free | −56 |
| **Population** | **12,404** |
| Removed by the fixed rules (too short, few letters, duplicates) | −1,312 |
| Removed by the content filter | −1,065 |
| **Filtered population** | **10,027** |
| **Coded sample** (simple random sample) | **1,200** |

The reviews are public content written by Steam users and are shared here only for research and to make the analysis verifiable.
If you are the author of a review and want it removed, open an issue.

The extracts file has one row per extract: review id, language, recommendation, playtime, theme, sub-theme, code, sentiment,
polarity, verbatim snippet, the proposals of each encoder, the justification of the adjudication, and the sub-theme before and
after the reassignment.

## Reproducing the analysis

Requirements: Python 3.9 or later with `httpx numpy pandas scipy statsmodels tqdm matplotlib`, [Ollama](https://ollama.com) with the
models below, and a LaTeX engine (for example tectonic) for the design brief.

| Role | Model (Ollama) | Digest |
|---|---|---|
| Filter, encoder 1, evaluation | `gemma4:latest` | 9ec987e7d068 |
| Encoder 2 | `qwen2.5:14b` | 7cdf5a0187d5 |
| Codebook naming, harmonization, evaluation, design brief | `phi4:latest` | ac896e5b8b34 |
| Embeddings | `nomic-embed-text:latest` | 0a109f422b47 |

Ollama 0.40.15, Q4_K_M quantization, temperature 0 (raised only to retry invalid JSON), seed 42; up to two requests at a time
during harmonization. Model outputs can differ slightly with other versions or hardware, which is why every output is stored here.

**To recompute the results from the stored outputs** (no model needed, except for the steps marked LLM), from `pipeline/`:

```bash
python ../scripts/06_analysis.py          # themes, sub-themes, models, comparisons -> results/
python ../scripts/09_design_triage.py     # triage groups -> results/design_triage.csv
python ../scripts/14_sample_size_cost.py  # cost and yield of smaller samples -> results/sample_size_cost.csv
python ../scripts/04_saturation.py        # saturation (embeddings) -> results/saturation_*.csv
python ../scripts/07_tables.py            # tables -> Paper/tables
python ../scripts/08_figures.py           # figures -> Paper/figures
python ../scripts/11_fig_pipeline.py      # pipeline figure
```

**To run the whole study again**, from `pipeline/`, in this order:

```bash
python ../scripts/01_population.py                          # Data/elex_population.json
python 0_filtering.py                                       # LLM: content filter
python stratified_sample.py                                 # sample of 1,200
python 1_encoding.py --config study_config_sample.json      # LLM: two encoders
python 2_harmonization.py --config study_config_sample.json # LLM: codebook and harmonization
python ../scripts/02_refine_system.py                       # LLM: the one manual change of the codebook, then a new test
python ../scripts/03_reassign_subthemes.py                  # LLM: sub-theme assignment
python ../scripts/05_subtheme_checks.py                     # LLM: order and drift checks
python 4_design_brief.py --config study_config_sample.json  # LLM: design brief
```

followed by the scripts above. In the pipeline repository, steps 03 and 05 are merged into `3_subtheme_assignment.py`, saturation is
`4_saturation.py` and the brief is `5_design_brief.py`; the procedure is the same.

## The one manual step

The codebook of *System* failed the codebook test (16.2% of codes unassigned, mostly on performance and on the absence of problems).
`scripts/02_refine_system.py` widens the definitions of three of its sub-themes, as written in the script, and tests the theme again
(κ = 0.88, 1.2% unassigned). The codebook before this change is kept in `subtheme_codebook_before_refinement.json`.
